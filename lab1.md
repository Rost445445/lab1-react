# Звіт з лабораторної роботи №1
**Тема:** Створення каркаса додатка та базових UI-компонентів.

## 1. Фрагмент коду (Компонент Card)
Компонент-обгортка, який використовує `props.children` для відображення вкладеного контенту:

```jsx
import styles from './Card.module.css';

const Card = ({ children }) => {
  return <div className={styles.card}>{children}</div>;
};

export default Card;





Відповіді на контрольні запитання
1. Що таке Atomic Design і навіщо ми розділяємо компоненти на атоми та молекули?
Atomic Design — це методологія архітектури інтерфейсів, яка передбачає поділ UI на найдрібніші незалежні частини (атоми, молекули, організми). Це робиться для того, щоб компоненти можна було легко перевикористовувати, уникати дублювання коду та підтримувати порядок у проєкті під час його масштабування.

2. Як працюють CSS Modules і як вони вирішують проблему глобальних імен класів?
CSS Modules локалізують стилі на рівні конкретного компонента. Під час збірки проєкту Vite автоматично генерує унікальні хеші для імен класів (наприклад, .button_xyz123). Завдяки цьому стилі з різних файлів ніколи не перетинаються і не конфліктують між собою, навіть якщо класи мають однакові назви.

3. Що таке props.children і в якому компоненті цієї лабораторної роботи ми його використали?
props.children — це спеціальний проп у React, який містить будь-який контент (текст, HTML-теги або інші компоненти), переданий між відкриваючим і закриваючим тегами компонента. У цій лабораторній роботі ми використали його в компонентах Card  та Button.

4. Чому атрибут HTML class у JSX записується як className?
JSX під капотом компілюється у звичайний JavaScript. Оскільки слово class є зарезервованим ключовим словом у JavaScript (використовується для створення JS-класів), розробники React змінили назву цього атрибута на className, щоб уникнути синтаксичних помилок.

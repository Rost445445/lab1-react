# Звіт з Практичної роботи №3: Логіка умовного відображення

## Частина 4: Контрольні запитання

### 1. Чому використання if/else безпосередньо всередині JSX-розмітки призведе до помилки?
JSX — це синтаксичний цукор для викликів функцій (наприклад, `React.createElement`). Аргументи функції в JavaScript повинні бути **виразами** (expressions), які повертають значення. 
`if/else` — це **інструкція** (statement), яка не повертає значення сама по собі. Тому її не можна вставити туди, де очікується вираз (всередині фігурних дужок `{}`). Замість цього використовуються вирази: тернарний оператор або логічне `&&`.

### 2. Яка небезпека криється у використанні числа 0 у лівій частині оператора && в JSX?
В JavaScript `0 && "text"` повертає `0`. Хоча `0` є "falsy" значенням для логіки, для React це цілком валідне число, яке він виведе на екран. 
**Приклад:** `{items.length && <List />}`. Якщо список порожній (`0`), на сторінці просто відобразиться цифра `0`, замість того щоб нічого не показувати. 
**Рішення:** Завжди приводити до булевого типу: `{items.length > 0 && <List />}` або `{!!items.length && <List />}`.

### 3. Як реалізувати умовний рендеринг, якщо варіантів відображення дуже багато (5+)?
Для великої кількості варіантів найкраще підходять:
- **Об'єктне відображення (Object mapping):** Створити об'єкт, де ключі — це стани, а значення — компоненти.
- **Винесення логіки в окрему функцію або компонент:** Використати `switch` або `if/else` всередині звичайної JS-функції, яка повертає потрібний JSX.
- **Окремі компоненти для кожного стану:** Це робить код чистішим і легшим для підтримки.

### 4. В яких випадках тернарний оператор кращий за &&?
- **Коли потрібна логіка "Якщо - Тоді - Інакше":** Якщо ви хочете показати або одне, або інше (наприклад, кнопку "Увійти" або "Вийти").
- **Для уникнення помилки з числом 0:** Тернарний оператор завжди вимагає обох гілок, тому ви точно контролюєте, що повертається у гілці "else".
- **Для динамічних атрибутів:** Наприклад, `{ className: isActive ? 'active' : 'inactive' }`. Оператор `&&` тут просто не підійде.

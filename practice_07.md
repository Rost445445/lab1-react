## 2. Опис виконання практичних завдань

У рамках цієї практичної роботи я впровадив динамічну маршрутизацію та фільтрацію коктейлів у свій навчальний проєкт. Завдяки цим інструментам вдалося значно покращити користувацький досвід, додавши можливість ділитися прямими посиланнями на конкретні рецепти та ділитися результатами пошуку із застосованими фільтрами.

### Динамічний маршрут та `useParams`

Для відображення сторінки з деталями конкретного коктейлю я налаштував динамічний маршрут у головному файлі додатку.

Фрагмент мого компонента `App.jsx`, де налаштовано маршрут `/cocktail/:id`:

```jsx
// App.jsx
import { BrowserRouter as Router, Routes, Route } from 'react-router-dom';
import CocktailsFeed from './pages/CocktailsFeed';
import CocktailDetails from './pages/CocktailDetails';

function App() {
  return (
    <Router>
      <Routes>
        <Route path="/" element={<CocktailsFeed />} />
        {/* Динамічний маршрут для сторінки деталей коктейлю */}
        <Route path="/cocktail/:id" element={<CocktailDetails />} />
      </Routes>
    </Router>
  );
}

export default App;
```

Для отримання відповідного ідентифікатора з URL та завантаження деталей я використав хук `useParams` у компоненті сторінки коктейлю.

Код компонента `CocktailDetails.jsx`:

```jsx
// CocktailDetails.jsx
import { useParams, Link } from 'react-router-dom';
import { useEffect, useState } from 'react';
// Припустимо, що у нас є функція для API-запиту коктейлю
import { fetchCocktailById } from '../api';

function CocktailDetails() {
  // Отримуємо параметр id з динамічного URL
  const { id } = useParams();
  const [cocktail, setCocktail] = useState(null);

  useEffect(() => {
    // Завантажуємо деталі змішаного напою базуючись на отриманому id
    fetchCocktailById(id).then(data => setCocktail(data));
  }, [id]);

  if (!cocktail) return <p>Завантаження...</p>;

  return (
    <div className="cocktail-details">
      <Link to="/" className="back-link">← Назад до всіх коктейлів</Link>
      <h1>{cocktail.name}</h1>
      <img src={cocktail.image} alt={cocktail.name} />
      <h3>Рецепт та інструкції:</h3>
      <p>{cocktail.instructions}</p>
    </div>
  );
}

export default CocktailDetails;
```

### Пошук, сортування та `useSearchParams`

Щоб стан пошуку та сортування зберігався під час перезавантаження сторінки або надсилання посилання іншому користувачу (наприклад: `/?query=margarita&sort=asc`), я реалізував їх через `useSearchParams` у стрічці коктейлів.

Код компонента списку коктейлів (`CocktailsFeed.jsx`):

```jsx
// CocktailsFeed.jsx
import { useSearchParams, Link } from 'react-router-dom';
import { useState, useEffect } from 'react';
import { fetchAllCocktails } from '../api';

function CocktailsFeed() {
  const [cocktails, setCocktails] = useState([]);
  
  // Ініціалізація хука useSearchParams для доступу до Query String
  const [searchParams, setSearchParams] = useSearchParams();
  
  // Зчитуємо поточні параметри з URL (або використовуємо дефолтні)
  const currentQuery = searchParams.get('query') || '';
  const currentSort = searchParams.get('sort') || 'asc';

  useEffect(() => {
    fetchAllCocktails().then(data => setCocktails(data));
  }, []);

  const handleSearchChange = (e) => {
    const text = e.target.value;
    // Оновлюємо URL-параметр query
    if (text) {
      searchParams.set('query', text);
    } else {
      searchParams.delete('query'); // Видаляємо параметр, якщо поле порожнє
    }
    setSearchParams(searchParams);
  };

  const handleSortChange = (e) => {
    // Оновлюємо URL-параметр sort
    searchParams.set('sort', e.target.value);
    setSearchParams(searchParams);
  };

  // Логіка фільтрації та сортування
  const displayedCocktails = cocktails
    // Спочатку фільтруємо масив за пошуковим запитом
    .filter(cocktail => 
      cocktail.name.toLowerCase().includes(currentQuery.toLowerCase())
    )
    // Потім застосовуємо сортування до відфільтрованого масиву
    .sort((a, b) => {
      if (currentSort === 'asc') {
        return a.name.localeCompare(b.name);
      } else {
        return b.name.localeCompare(a.name);
      }
    });

  return (
    <div className="feed-container">
      <h2>Каталог коктейлів</h2>
      
      <div className="filters-bar">
        {/* Інпут пошуку синхронізований з параметром currentQuery */}
        <input 
          type="text" 
          placeholder="Пошук коктейлю за назвою..." 
          value={currentQuery}
          onChange={handleSearchChange}
        />
        
        {/* Випадаючий список синхронізований з параметром currentSort */}
        <select value={currentSort} onChange={handleSortChange}>
          <option value="asc">Від А до Я</option>
          <option value="desc">Від Я до А</option>
        </select>
      </div>

      <div className="cocktail-list">
        {displayedCocktails.map(cocktail => (
          <div key={cocktail.id} className="cocktail-card">
            <h3>{cocktail.name}</h3>
            <Link to={`/cocktail/${cocktail.id}`}>Переглянути рецепт</Link>
          </div>
        ))}
        {displayedCocktails.length === 0 && <p>За вашим запитом коктейлів не знайдено.</p>}
      </div>
    </div>
  );
}

export default CocktailsFeed;
```

## 3. Відповіді на контрольні запитання

**1. Поясніть принципову різницю між URL-параметрами шляху (Path Parameters, наприклад `/users/42`) та параметрами запиту (Query Parameters, наприклад `/users?sort=asc`). В яких випадках який підхід слід використовувати?**

*   **Path Parameters (Параметри шляху):** Є структурною частиною самого URL. Вони ідентифікують конкретний ресурс у системі чи його конкретний пункт призначення. Якщо видалити цей параметр, URL втратить свій сенс, або вкаже абсолютно на іншу сторінку.
    *   *Коли використовувати:* Для ідентифікації сутностей, наприклад, при відкритті сторінки конкретного користувача (`/users/42`), окремого коктейлю (`/cocktail/7`) або блог-посту.
*   **Query Parameters (Параметри запиту):** Йдуть після знаку `?` і являють собою додаткові опції у вигляді пар "ключ-значення" (наприклад, `?sort=asc&query=margarita`). Вони є "необов'язковими" і не змінюють сам ресурс, а лише модифікують його вигляд або форму.
    *   *Коли використовувати:* Для пошуку, фільтрації, сортування, пагінації (`?page=2`) на сторінках списків. Якщо їх прибрати, сторінка продовжуватиме працювати, показуючи інформацію за замовчуванням (без застосованих налаштувань).

**2. Що робить хук `useParams()` і який обов'язковий синтаксис необхідно використати в визначенні `<Route path="...">` для того, щоб цей хук запрацював?**

Хук `useParams()` (з бібліотеки `react-router-dom`) дозволяє компоненту отримати доступ до динамічних параметрів зі збігу поточного URL-шляху. Він повертає об'єкт пар "ключ-значення".
Для того, щоб цей хук запрацював, під час налаштування маршрутів в параметрі `path` компонента `<Route>` необхідно використати синтаксис із **двокрапкою** `:` перед назвою змінної шляху. 
*Приклад:* `<Route path="/cocktail/:id" element={<CocktailDetails />} />`. Тут `:id` — це обов'язково зазначений шаблон, який зробить ідентифікатор доступним як `const { id } = useParams()`.

**3. Чому зберігання стану пошукового рядка (Search Bar) в URL (через `useSearchParams`) вважається архітектурно кращим рішенням, ніж зберігання його у локальному стані компонента (`useState`)? Опишіть переваги для кінцевого користувача.**

Зберігання вибірки в URL робить ці параметри частиною глобального маршрутизованого стану додатка, що дає кінцевому користувачу такі суттєві переваги:
1.  **Можливість обміну посиланнями (Sharable URLs):** Користувач може скопіювати посилання (напр. з вже введеним пошуковим запитом і вибраним сортуванням) та відправити його другу. При переході одержувач побачить точно ті ж самі результати фільтрації.
2.  **Навігація (Browser History):** Користувач може використовувати кнопки браузера "Назад" і "Вперед", щоб повернутися до попереднього стану пошуку. З локальним `useState` цього зробити не можна (параметри одразу затруться).
3.  **Закладки (Bookmarks):** Будь-який специфічний результат пошуку чи фільтрації списку можна зберегти у закладки браузера.
4.  **Стійкість до перезавантаження:** Якщо з якоїсь причини користувач перезавантажить сторінку екрану браузера (натисне F5), результати пошуку не зникнуть — адже вони будуть заново зчитані з URL.

**4. Якщо ви використовуєте метод масиву `filter()` прямо перед поверненням JSX-розмітки, чи відбувається ця фільтрація при кожному рендері компонента? Як це може вплинути на продуктивність для дуже великих масивів (напр. 10 000+ елементів) і який інший React-хук ви б використали для оптимізації?**

Так, якщо метод `filter()` написано безпосередньо у тілі компонента поза межами інших хуків, цей синхронний обхід масиву **відбуватиметься заново під час кожного рендеру** цього компонента (щоразу коли буде змінюватися якийсь стан або надходити нові пропси).
Для невеликих масивів це малопомітно, проте для масивів у 10 000+ елементів відбудеться помітна затримка (CPU bottleneck), адже блокуватиметься головний потік браузера — інтерфейс може "задизатися", анімації підвисатимуть (знизиться FPS).
Для оптимізації такого сценарію слід завжди використовувати хук **`useMemo()`**. Він запам'ятовує (кешує) результати складної операції фільтрації та перераховує їх лише тоді, коли змінюється сам масив елементів або залежні параметри фільтрації.

**5. В яких об'єктах стандарту Web API у звичайному (базовому) JavaScript зберігаються параметри після знаку питання `?`, і як React Router спрощує роботу з ними?**

У звичайному Vanilla JavaScript інформація, розміщена після знаку питання, доступна як рядок у властивості `window.location.search`. Для того щоб розібрати цей рядок (розпарсити) на зручні пари "ключ-значення", стандарт Web API пропонує об'єкт класу **`URLSearchParams`**.
React Router значно спрощує роботу через свій хук `useSearchParams()`. Замість того, щоб вручну писати код для ініціалізації об'єкта, зміни історії в `window.history.pushState` та примусового перерендеру списку, хук `useSearchParams()`:
1. Одразу повертає готовий екземпляр `URLSearchParams`.
2. Повертає функцію-сеттер (схожу на `setState`), яка автоматично записує параметри в URL без перезавантаження всієї сторінки браузером.
3. Додаток залишається реактивним: після зміни URL список автоматично перерендериться з новими параметрами, бо React Router "піймає" цю зміну.

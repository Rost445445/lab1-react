# Звіт з Практичної роботи №4: Валідація введених даних у React

## Частина 4: Контрольні запитання

### 1. У чому головна різниця між керованими (controlled) та некерованими (uncontrolled) компонентами?
- **Керовані компоненти:** Стан інпуту повністю контролюється React-компонентом через `useState`. Значення (`value`) прив'язане до стану, а будь-яка зміна обробляється через `onChange`. Весь "усвідомлений" стан перебуває в React.
- **Некеровані компоненти:** Стан інпуту зберігається в самому DOM. React отримує доступ до значення тільки тоді, коли воно потрібне (наприклад, при відправці форми), зазвичай за допомогою `ref`.

### 2. Навіщо використовувати useRef при роботі з некерованими компонентами?
`useRef` надає прямий доступ до DOM-вузла. Оскільки в некерованих компонентах React не відстежує кожен введений символ через стан, `ref` є єдиним способом "дістати" поточне значення з текстового поля в потрібний момент (наприклад, `inputRef.current.value`).

### 3. Що робить метод event.preventDefault() під час відправки форми і чому він важливий у React-додатках?
Цей метод скасовує стандартну поведінку браузера — перезавантаження сторінки та відправку GET/POST запиту на сервер при натисканні кнопки `submit`. 
**Чому це важливо:** В Single Page Applications (SPA), таких як React, ми хочемо обробити дані самостійно через JavaScript (валідація, відправка через API), не втрачаючи при цьому стан додатка, що стався б при перезавантаженні.

### 4. Як реалізувати валідацію так, щоб помилка з’являлася лише після того, як користувач вперше взаємодіяв з полем (dirty fields)?
Це можна зробити, додавши стан "забрудненості" (`isDirty` або `touched`) для кожного поля:
1. Створити об'єкт стану: `const [touched, setTouched] = useState({ name: false, score: false });`.
2. Додати обробник `onBlur` до інпутів, який встановлює `touched[fieldName] = true`.
3. Виводити помилку лише за умови: `{touched.name && errors.name && <span>{errors.name}</span>}`.
Таким чином, користувач не бачитиме червоних написів на щойно відкритій порожній формі.

# Звіт з Лабораторної роботи №2

## Тема: Реалізація стрічки новин або списку об'єктів у React

### 1. Фрагмент коду з App.jsx (.map())
```jsx
<main className="feed">
  {posts.map(post => (
    <Post 
      key={post.id} 
      {...post} 
    />
  ))}
</main>
```

### 2. Пояснення щодо пропса `key`
Якщо видалити атрибут `key` у списку, React не зможе ефективно відстежувати, які елементи змінилися, були додані або видалені.
**Наслідки:**
- В консолі розробника з'явиться попередження: `Warning: Each child in a list should have a unique "key" prop.`
- Погіршиться продуктивність при оновленні списку.
- Можуть виникнути помилки зі станом компонентів (наприклад, стан лічильника лайків може "перестрибнути" на інший пост при сортуванні чи видаленні).

## Відповіді на контрольні запитання

### 1. Навіщо потрібен проп key у списках React? (Reconciliation)
Проп `key` допомагає React ідентифікувати, які саме елементи в списку змінилися. Під час процесу **Reconciliation** (узгодження) React порівнює поточне дерево Virtual DOM із попереднім. Без ключів React змушений повністю перемальовувати весь список при зміні хоча б одного елемента. Ключі дозволяють React повторно використовувати існуючі DOM-вузли, що значно пришвидшує роботу.

### 2. Чому не рекомендується використовувати індекс масиву (index) як ключ?
Використання `index` є небезпечним, якщо порядок елементів у списку може змінюватися (фільтрація, сортування, додавання в початок). Якщо ми змінимо порядок, індекс елемента зміниться, і React "подумає", що це зовсім інший компонент. Це призведе до некоректного відображення стану (наприклад, введення в інпут або стан перемикача залишиться на тій же позиції, хоча дані змістилися).

### 3. У чому різниця між імперативним створенням списку (цикл for) та декларативним (map)?
- **Імперативний підхід (for):** Ми описуємо *як* саме потрібно створити список: створити порожній масив, пройтися циклом, вручну додати кожен елемент (методом push). Це складніше підтримувати та легше припуститися помилки.
- **Декларативний підхід (map):** Ми описуємо *що* ми хочемо отримати: "перетворити кожен об'єкт даних на компонент Post". Це коротше, зрозуміліше і краще вписується в ідеологію React.

### 4. Як передати всі властивості об'єкта в компонент одним рядком?
Для цього використовується **spread-оператор** (`...`):
```jsx
<Post {...post} />
```
Це еквівалентно написанню: `id={post.id} author={post.author} content={post.content} ...`

## Інструкція з розгортання на GitHub Pages

Щоб опублікувати ваш проєкт на GitHub Pages, виконайте наступні кроки у вашому терміналі:

1. **Встановіть залежності (якщо ще не встановлено):**
   ```bash
   npm install
   ```

2. **Запустіть скрипт деплою:**
   ```bash
   npm run deploy
   ```

**Що відбувається при виконанні цієї команди?**
- `npm run predeploy` автоматично запустить `npm run build`, щоб створити оптимізовану папку `dist/`.
- `gh-pages -d dist` завантажить вміст папки `dist` у спеціальну гілку `gh-pages` вашого репозиторію.
